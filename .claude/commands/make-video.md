# 分工
- **你（Claude）**：写脚本、选配色、剪辑、渲染、自检，交付成片和发布文案。
- **用户**：只决定上不上传。不要替用户上传或发布到任何平台。

输入：`$ARGUMENTS`。信息不足时用合理默认值直接出片，不要反问。

## 1. 写脚本（写入 `video/specs/<短英文名>.json`）
格式见 `video/specs/example.json`。规则：
- `title`：第 0 帧就会显示，也是封面。≤ 12 个字，必须是钩子（数字、反差、利益点），不要寒暄。
- `subtitle`：≤ 14 个字，补一个悬念或具体承诺。
- `captions`：3–4 句，每句 ≤ 12 个字（一屏读完），一句一个镜头。
- `ending`：≤ 10 个字，行动号召（收藏 / 关注 / 评论关键词）。
- `theme`：sunset / ocean / forest / night 中选一个，与主题情绪匹配。
- `images`：用户给了素材就按镜头顺序填路径（相对 spec 文件），否则留空，自动生成画面。

## 2. 渲染
```
cd video && npm install --silent && node render.mjs specs/<名字>.json
```
输出到 `video/out/<名字>.mp4`。

## 3. 自检（必须做，不通过就改了重渲）
- `ffprobe` 确认：h264、1080x1920、30fps、aac、时长 10 秒。
- 在 0.0s / 3s / 6s / 9.5s 抽帧，拼成一张图查看：文字有没有超出画面、有没有被截断，字幕是否在画面中上部（底部 25% 和右侧按钮列会被平台界面挡住）。

## 4. 交付
用 SendUserFile 发出 mp4 和抽帧拼图，再附上可直接复制的发布文案：
- **YouTube Shorts**：标题（≤ 100 字符，含 `#Shorts`）+ 3–5 个 hashtag。
- **小红书**：标题（≤ 20 字）+ 正文 2–4 行 + 5–8 个话题标签。

最后一句问用户：是否上传，或者要改哪里。
